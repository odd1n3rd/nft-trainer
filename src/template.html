Отправить пакет

Формат: <iif|-> <tcp|udp|icmp> <src[:port]> > <dst[:port]> [флаги]. «-» значит, что пакет отправляет сам хост. TCP-флаги через запятую (по умолчанию syn), тип ICMP по имени, ct=invalid|related задаёт состояние, x20 — пачка из 20 пакетов.

Путь пакета через хуки netfilter

Хуки с одинаковым именем срабатывают по возрастанию priority. accept в одной базовой цепочке не спасает от drop в другой на том же хуке. Чтобы пакет прошёл, его должны принять все цепочки, через которые он идёт.

Скелет файла

#!/usr/sbin/nft -f
flush ruleset

define ADMIN = 10.10.0.0/24

table inet filter {
  set blocklist {
    type ipv4_addr; flags interval
    elements = { 192.0.2.0/24 }
  }
  chain input {
    type filter hook input priority filter; policy drop;
    ct state established,related accept
    ct state invalid drop
    iifname "lo" accept
    ip saddr @blocklist drop
    ip saddr $ADMIN tcp dport 22 accept
  }
}

# трассировка, как в тренажёре
nft add rule inet filter prerouting \
  ip saddr 198.51.100.7 meta nftrace set 1
nft monitor trace
# страховка от потери доступа
nft -f new.conf; sleep 60; nft -f old.conf

Что моделирует тренажёр

Только IPv4. Семейства ip и inet, хуки prerouting / input / forward / output / postrouting, цепочки filter и nat с приоритетами, conntrack (new, established, повтор первого пакета), DNAT, SNAT, masquerade, redirect с обратной трансляцией ответов, анонимные и именованные множества, define, jump, goto, return, log, counter, limit, reject.

Не моделируются: IPv6-трафик (правила ip6 разбираются, но не совпадают), map/vmap, конкатенации, flowtable, таймауты conntrack, фрагментация. limit упрощён: пакеты одной пачки приходят одновременно, проходят первые burst штук.
