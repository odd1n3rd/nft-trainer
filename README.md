# nft-тренажёр

Интерактивный тренажёр nftables в браузере. Вы пишете набор правил, через него проходят тестовые пакеты, а тренажёр показывает путь каждого пакета: хуки netfilter, сработавшие правила, conntrack, NAT и итоговый вердикт. Ничего не нужно ставить, и SSH на живом сервере не отвалится.

## Что внутри

**12 уровней** от первого правила до проброса портов:

| # | Уровень | Тема |
|---|---------|------|
| 1 | Первое правило | таблица, цепочка, hook, вердикт |
| 2 | Запрещено всё, что не разрешено | `policy drop`, loopback |
| 3 | Память соединений | `ct state established,related`, `invalid` |
| 4 | Множества в фигурных скобках | анонимные множества |
| 5 | Именованные множества и define | `set`, `flags interval`, `define` |
| 6 | ICMP и ограничение частоты | `icmp type`, `limit rate` |
| 7 | drop или reject | `reject with tcp reset`, `iifname` |
| 8 | Свои цепочки | `jump`, `goto`, `return`, `log` |
| 9 | Маршрутизатор | цепочка `forward` |
| 10 | NAT: маскарадинг | `masquerade` |
| 11 | Проброс порта | `dnat`, `ct status dnat` |
| 12 | Аудит чужого конфига | найти четыре ошибки |

**Песочница:** шлюз с WAN и LAN, произвольный набор правил, отправка пакетов вручную. Таблица conntrack сохраняется между пакетами, так что видно, как ответ становится `established` и как NAT транслируется обратно.

**Справочник:** схема хуков, приоритеты, шпаргалка по выражениям и действиям, команды для живой системы.

Ошибки разбора выводятся в формате nft (`/etc/nftables.conf:6:22-33: Error: …`), с подчёркиванием фрагмента и подсказкой. Где возможно, сохранены настоящие тексты ошибок nft.

## Что моделируется

Только трафик IPv4. Семейства `ip` и `inet`; хуки prerouting, input, forward, output и postrouting; цепочки filter и nat с приоритетами; conntrack (new, established, повтор первого пакета, related и invalid задаются в тесте); DNAT, SNAT, masquerade и redirect с обратной трансляцией; анонимные и именованные множества; `define`; `jump`, `goto`, `return`, `log`, `counter`, `limit`, `reject`, `meta mark set`.

Чего нет: IPv6-трафика (правила `ip6` разбираются, но не совпадают), `map` и `vmap`, конкатенаций, flowtable, таймаутов conntrack. `limit` упрощён: пакеты одной пачки приходят одновременно, проходят первые `burst` (по умолчанию 5).

## Разработка

Код без зависимостей, нужен только Node.js 18 или новее.

```bash
npm run build      # собрать public/index.html из src/
npm test           # прогнать эталонные решения и стартовые конфиги через симулятор
npm run check:nft  # проверить их настоящим nft (nft -c -f) в Docker
npm start          # отдать public/ на $PORT (по умолчанию 8080)
```

- `src/engine.js` — парсер подмножества nft и симулятор netfilter;
- `src/levels.js` — уровни, топологии и тестовые пакеты;
- `src/app.js`, `src/template.html` — интерфейс.

### Как добавить уровень

Уровень — это объект в `LEVELS` (`src/levels.js`): текст задачи и теории, стартовый конфиг, эталонное решение, подсказки и потоки тестовых пакетов. Пакет записывается одной строкой:

```
<iif|-> <tcp|udp|icmp> <src[:port]> > <dst[:port]> [флаги] [ct=invalid|related] [xN]
eth0 tcp 198.51.100.7:51000 > 203.0.113.10:22 syn
-    udp 203.0.113.10:53000 > 8.8.8.8:53          # «-» — пакет отправляет сам хост
```

Ожидание `e` может быть `accept`, `drop`, `reject`, `deny` (drop или reject) или `mixed` (часть пачки проходит). Дополнительно можно проверить результат NAT (`nat: { src, dst, sport, dport }`), выходной интерфейс (`oif`), тип отказа (`rejectWith`) и запись в журнал (`log`). Пакеты внутри одного потока делят conntrack.

Прежде чем отправлять PR, прогоните `npm test` и `npm run check:nft`.
